# Backstage learning and cooperation evaluations

Acceptance targets, not results or mandatory in-game examinations. Agents begin without the authored example packages and generate their own methods from actual game experience. A model must choose the actions. Fixtures may construct the starting state and evaluate outcomes; they may not prescribe the actor's tool sequence.

| Pressure-2 | Hose disconnects after a successful repair | New observation changes diagnosis; no false completion | Needs disconnect/damage incident tools |
| Teaching-1 | Teammate is unavailable on the transfer trial | Learner chooses another allocation; outcome attributable to learner calls | Needs training persistence/evaluator and model harness |

Compare matched world states with learned memory retained versus reset, and separately with actor messaging enabled versus disabled. Repeat runs and do not require a predetermined skill name, graph or action sequence. Measure completed incidents, player interventions, idle time, duplicate claims, abandoned posts, latency and actual provider usage separately from game oxygen. A useful skill should improve observed play, not merely produce confident explanations.
